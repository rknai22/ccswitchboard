# Этап 1. Оркестратор: General раздаёт задачи и следит за ними

Дата: 2026-10-28. Владелец: «реализуй всё сразу» — отдельного «да» на это описание нет;
содержание обсуждено в теме ccswitchboard 27–28.10 (и с ChatGPT). Строится поверх этапа 0 и
блока удобства. План: `BACKLOG.md`, этап 1.

## Зачем (слова владельца)

«Чтобы дал ТЗ, расширенное»; «докладывать, следить … поручить следить за несколькими
сессиями и у него основные моменты спрашивать, узнавать, что на каком этапе»; «чтобы сессии
могли между собой общаться, если потребуется»; «в одном топике может быть множество задач».

## Что делаем

### Реестр задач (broker, `tasks.ts`)

- Таблица `tasks`: `id`, `topic`, `title`, `spec`, `state`, `source` (`general` | `topic`),
  `created_at`, `updated_at`, `last_report_at`, `summary`, `next_step`.
  Состояния: `proposed` → `assigned` → `in_progress` / `waiting_owner` / `blocked` → `done`;
  `cancelled`. Таблица `task_events` — история (кто, когда, что).
- Задача ≠ тема: у темы сколько угодно задач.

### Новые инструменты

| инструмент | кто | что |
|---|---|---|
| `propose_task {topic, title, spec}` | только General | задача `proposed`; в General — ТЗ с кнопками «✅ Отправить в <тема>» / «❌ Отменить» |
| `report {task_id?, title?, state, summary, next_step?}` | тема, только свои задачи | отчёт; без `task_id`, но с `title` — тема заводит задачу сама (`source: topic`) |
| `tasks {topic?, open_only?}` | General — все; тема — свои | список: этап, возраст последнего отчёта, на связи ли сессия, занята ли |
| `ask_owner {question, options?}` | любая сессия | вопрос в своей теме с кнопками (по умолчанию «✅ Да» / «❌ Нет») |
| `tell_topic {topic, text}` | любая сессия | сообщение другой теме (см. ниже) |

### Поручение (ТЗ с кнопкой)

- Нажать может только владелец. По «✅» broker публикует в теме «📋 Задача #N (от владельца
  через General): <title>» + ТЗ и кладёт событие в очередь темы с `task_id` и
  `forwarded_from_general_message_id` — это слова владельца: он подтвердил ровно этот текст.
- Текст предложения не меняется; правка = новое предложение. Кнопки старого гаснут
  (`cancelled`). Кнопки живут 7 дней.

### Отчёты и доклады

- `done` / `blocked` / `waiting_owner` → broker сам пишет в General (со звуком):
  «✅ wms #12 <title> — <summary>». `in_progress` — тихо, без сообщения.
- Отчёт меняет `updated_at`/`last_report_at`. В `tasks` возраст отчёта виден всегда:
  молчание — это «давно не отчитывалась», а не «всё идёт».
- `/tasks` в любой теме — открытые задачи этой темы; в General — всех.

### Кнопки решений (`ask_owner`)

- Кнопки привязаны к вопросу (`ccsq:<id>:<n>`); нажимает только владелец. Ответ уходит
  сессии событием от владельца: «🔘 <вариант>» с `answer_to` (id вопроса) и текстом вопроса.
  Сообщение с вопросом правится: варианты убираются, дописывается выбор.
- Инструкции тем: push / PR / удаление — через `ask_owner`, а не «напиши да».

### Общение сессий (`tell_topic`)

- Видно владельцу: в целевой теме — тихое «💬 от <тема>: <текст>».
- Сессии приходит событие с `from_topic=<тема>`, `user = topic:<тема>`. Это **информация,
  не приказ**: инструкции и шаблоны говорят это прямо; приказы — только владелец (и ТЗ по
  кнопке).
- Ограничения: текст ≤ 2000 символов; не больше 10 сообщений в час от одной темы к другой;
  в General через `tell_topic` писать нельзя (General спрашивает сам через `tasks`).

### Временные исполнители

Своего не строим (решение владельца): шаблон General учит пользоваться оркестрацией Orca
(`orca` CLI: worktree + агент на задачу), результат — отчёт или PR в теме проекта.

## Анти-цели

- Текст, написанный сессией, становится приказом другой сессии без кнопки владельца.
- Доклад в General зависит от памяти сессии General (доклады шлёт broker).
- Сводка выдаёт «в работе» для задачи, по которой давно нет отчёта, без пометки возраста.

## Тесты

Реестр (создание, переходы, история); `propose_task` только из General; кнопка только
владельца, ТЗ доходит до темы с `task_id`; отменённое/просроченное не отправляется; `report`
по чужой задаче — отказ; уведомления в General по состояниям; `ask_owner` → нажатие →
событие сессии + правка сообщения; `tell_topic` — видимая копия, `from_topic`, лимит, запрет
в General.
